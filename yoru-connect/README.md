# Yoru Connect

Серверный пилот для собственного VPN-узла WireGuard. Он выдаёт параметры подключения, проверяет права и обновляет список разрешённых устройств. Пользовательский ключ генерируется на устройстве. В базе хранятся идентификаторы учётных записей, хеши токенов, публичные ключи, адреса туннелей и сроки доступа. Сервису не нужны данные для входа в Telegram.

## Доступ

| План | Условия пилота |
| --- | --- |
| FREE | Клиент YoruGram и пользовательские прокси работают независимо. Управляемый VPN требует пробного доступа или ECLIPSE. |
| ECLIPSE | Предложение для пилота — 149 ₽ в месяц за управляемый VPN, до двух устройств. Оплата и автопродление пока не подключены. |
| OWNER / DEVELOPER | Сервер назначает роль одной учётной записи. Доступ стоит 0 ₽, не истекает и не зависит от подписки Telegram. |

Пробный период начинается по запросу пользователя, длится семь суток и доступен один раз на учётную запись. После окончания периода узел исключает ключи устройства при следующей синхронизации. Продление доступа оператор выполняет локальной командой после подтверждения оплаты. Регистрацию аккаунта и повышение роли HTTP API не предоставляет.

## Установка для закрытого пилота

Используйте выделенную Linux VM с WireGuard, systemd, Python 3.12 и отдельным DNS-именем для HTTPS API. Перед использованием в России проверьте актуальные требования к VPN и условия хостинга. Развёртывание через эти команды предполагает разрешённый узел с собственным публичным адресом.

1. Создайте системного пользователя `yoru-connect` без оболочки входа. Разместите содержимое этой папки в `/opt/yoru-connect`. Создайте виртуальную среду `python3 -m venv .venv` и установите `.venv/bin/pip install -r requirements.txt`.
2. Установите `wireguard-tools`. Создайте выделенный интерфейс `wg-yoru` через `wg-quick`. Для него зарезервированы `10.70.0.1/24` и `fd70:7952:7500::1/64`. Сгенерируйте ключ сервера командой `wg genkey` в доступный только root файл `/etc/wireguard/yoru.key`. Внесите этот ключ в конфигурацию интерфейса с правами 0600. Оставьте `SaveConfig` выключенным. Включите `wg-quick@wg-yoru.service`.
3. Настройте входящий UDP-порт WireGuard и IPv4-форвардинг на узле. В разрешённых правилах firewall разрешите форвардинг от `wg-yoru` только на выбранный внешний интерфейс и обратный трафик установленных соединений. Пример таблицы IPv4 forwarding и masquerade находится в `deploy/forwarding.nft.example`. Скопируйте его, замените `eth0`, согласуйте новые правила с существующим firewall и проверьте синтаксис через `nft -c -f` перед применением. Пример пропускает IPv4 в Интернет, блокирует прямой обмен между VPN-устройствами и IPv6-форвардинг. Для выдачи IPv6-выхода нужны отдельная маршрутизация и правила фильтрации. Конфигурация клиента направляет IPv6 в туннель даже при отсутствии IPv6-выхода на узле. Проверьте это до пилота, чтобы клиенты не отправляли IPv6 вне туннеля.
4. Скопируйте `deploy/settings.env.example` в `/etc/yoru-connect/settings.env`. Укажите публичный адрес и порт, выбранный DNS-резолвер и публичный ключ из `wg pubkey < /etc/wireguard/yoru.key`. API слушает только loopback. Настройте обратный прокси с валидным TLS-сертификатом по `deploy/Caddyfile.example`; не публикуйте внутренний порт 8074.
5. Установите три файла systemd из `deploy/`, перезапустите чтение конфигурации systemd и включите `yoru-connect.service` и `yoru-connect-wireguard.timer`. API работает без прав управления сетью. Отдельный процесс обновляет ключи выделенного интерфейса и удаляет просроченные через короткие интервалы.
6. На сервере, из `/opt/yoru-connect`, выдайте первый токен владельца:

   ```sh
   sudo -u yoru-connect .venv/bin/python -m yoru_connect.admin create giova355 --owner
   ```

   Передайте его владельцу по защищённому каналу. Локальные команды `create`, `rotate-token`, `disable` и `grant --days 30` доступны оператору сервера. Смена токена включает учётную запись и аннулирует старый токен. Отключение отзовёт все её профили.

## Подключение

В закрытом пилоте используйте стандартный клиент WireGuard. На доверенном компьютере с утилитой `wg` выполните `python -m yoru_connect.profile https://ВАШ-ДОМЕН имя.conf`. Утилита запросит токен без отображения, зарегистрирует публичный ключ и сохранит новый профиль. Импортируйте файл в WireGuard через защищённый канал и удалите ненужные копии. При пробном доступе сначала вызовите `POST /v1/trial` с заголовком `Authorization: Bearer …` через доверенный HTTPS-клиент.

Профиль использует MTU 1280 и keepalive каждые 25 секунд. Это начальные настройки для мобильной сети. Успешная выдача профиля не подтверждает доступность UDP. Подключение проверяйте по WireGuard handshake и запросам через туннель. У API один настроенный узел, отдельная работа предстоит для распределённого управления, резервирования между хостами и интеграции управления VPN в YoruGram.

## Проверки

```sh
python -m pip install -r requirements-test.txt
python -m unittest discover -v -s tests
sudo bash tests/wireguard-smoke.sh "$(command -v python)"
```

Последняя команда требует Linux с модулем WireGuard и правами на создание сетевых пространств имён. Она создаёт изолированные сервер и клиент, проверяет IPv4 и IPv6 внутри туннеля, IPv4 NAT на отдельном тестовом выходном сегменте и прекращение трафика после отключения участника.

При полевом пилоте проверяйте T2, Билайн, МТС и МегаФон отдельно. Запишите регион, тип сети, время handshake, повторный запуск после авиарежима, переключение LTE/5G ↔ Wi‑Fi, DNS и задержку. Отдельно зафиксируйте случаи, когда маршрут до узла недоступен. Опубликовать цену и обещания покрытия можно после правовой проверки и фактических испытаний.
