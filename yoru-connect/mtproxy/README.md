# Yoru Connect MTProxy

Выделенный узел для подключения Telegram и YoruGram по MTProto. Подходит для меню «Add Proxy» и подключения до входа в аккаунт. Сервер использует закреплённую ревизию [Telegram MTProxy](https://github.com/TelegramMessenger/MTProxy/tree/96cfd2faeeb6f0c98a79b5d2c5f1dc94fdff3806) и получает маршруты к дата-центрам с `core.telegram.org`. Для запуска узла достаточно собственного хоста и локально сгенерированного ключа прокси. Через него идёт трафик Telegram.

## Сборка и установка на Linux x86-64

Требуется Linux с systemd 250 или новее. Пример для Ubuntu 24.04. Команды выполняются из этого каталога.

```sh
sudo apt-get install -y build-essential git libssl-dev zlib1g-dev python3
bash build.sh ./build
sudo install -d -m 0755 /opt/yoru-mtproxy /etc/yoru-mtproxy
sudo install -m 0755 ./build/mtproto-proxy /opt/yoru-mtproxy/
sudo install -m 0644 proxyctl.py /opt/yoru-mtproxy/
sudo /usr/bin/python3 /opt/yoru-mtproxy/proxyctl.py init
sudo install -m 0644 yoru-mtproxy.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now yoru-mtproxy
```

По умолчанию узел принимает подключения IPv4 на TCP 443. Разрешите входящий TCP 443 в настройках хоста и облачного firewall. Статистика доступна на `127.0.0.1:2399`. Когда 443 уже занят, задайте `YORU_MTPROXY_PORT=8443` в `/etc/yoru-mtproxy/service.env` и разрешите соответствующий TCP-порт. Если хост выходит в Интернет через NAT с фиксированным публичным IPv4, добавьте туда `YORU_MTPROXY_NAT_ARGS="--nat ЛОКАЛЬНЫЙ_IPv4:ПУБЛИЧНЫЙ_IPv4"` и перезапустите службу. Входящее перенаправление порта настраивается отдельно на стороне хостинга.

## Подключение

```sh
python3 /opt/yoru-mtproxy/proxyctl.py status
sudo /usr/bin/python3 /opt/yoru-mtproxy/proxyctl.py link ВАШ_ДОМЕН_ИЛИ_IP
```

Добавьте `--port 8443` к команде `link`, если настроили этот порт. Откройте полученную ссылку на телефоне или введите значения `server`, `port` и `secret` вручную в **Add Proxy → MTProto**. Префикс `dd` в секрете включает случайное дополнение пакетов в поддерживаемых клиентах. Ссылка даёт доступ к узлу любому получателю. Передавайте её приватно, в том числе владельцу проекта. Развёртывание на VPS может оплачиваться отдельно.

## Обслуживание и проверка

- `status` выводит число готовых маршрутов Telegram и возвращает ошибку при нуле. При сбое посмотрите `journalctl -u yoru-mtproxy`. Тест клиента после запуска — открыть Telegram через прокси в нужной сети и проверить соединение до входа.
- Раз в сутки запускайте `sudo /usr/bin/python3 /opt/yoru-mtproxy/proxyctl.py refresh`. При появлении новых файлов перезапустите службу, чтобы применить их. При сбое скачивания продолжит действовать предыдущая конфигурация. После успешного перехода старые каталоги `relay-*` можно удалить, сохранив цель ссылки `relay`.
- При смене ключа выполните `rotate-key` через ту же утилиту и перезапустите службу. Оба ключа работают в период перехода. Получите новую ссылку командой `link`, затем выполните `retire-key` и перезапустите службу для отзыва старого ключа. Перезапуск прерывает активные подключения.
- Для резерва разверните второй хост с отдельным ключом и добавьте обе ссылки в настройки прокси клиента. Проверяйте каждую точку с SIM T2, Билайн, МТС, МегаФон и из домашней Wi-Fi сети. Фиксируйте регион, оператора, соединение до входа, задержку в клиенте и повторное подключение. Встроенная диагностика узла проверяет связь с Telegram со стороны сервера.
- `python3 smoke.py ./build/mtproto-proxy` проверяет собранный бинарник, доступность портов, отсутствие ключей в аргументах процесса и смену ключа. Режим `--live` с Telethon 1.46.0 запрашивает ответ Telegram через узел до входа под обоими ключами. При NAT передайте параметр `--nat ЛОКАЛЬНЫЙ_IPv4:ПУБЛИЧНЫЙ_IPv4`.
